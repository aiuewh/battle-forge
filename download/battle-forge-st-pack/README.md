# ⚔ Battle Forge · D&D 2024 战斗前端 —— 酒馆集成包（结算权威版 v2）

> **本版核心变化：结算权威 = 前端面板。**
> 战斗的全部规则结算（命中 / 伤害 / 豁免 / 状态 / 回合 / 移动 / 敌我 AI）在面板内完成；
> AI DM 只负责三件事：**战前设计详细敌情（<encounter>）→ 触发战斗（<battle>）→
> 收到战报（<battleresult>）后叙述战后剧情并应用变量更新**。
> AI 不再从头到尾叙事战斗，杜绝"AI 结算与面板数值双轨"的冲突。

## 文件清单

| 文件 | 用途 |
|------|------|
| `battle-forge-panel.json` | 核心正则脚本（导入酒馆 Regex，**拖到列表最顶部**） |
| `battle-forge-hide-legacy.json` | 隐藏 4 楼以前消息里的原始协议文本（可选但建议） |
| `battle-protocol-worldbook-entry.txt` | 世界书条目：教 AI 三阶段战斗协议（粘贴进角色卡） |
| `bootstrap-template.html` | bootstrap 源模板（正则包由它生成，一般不用动） |
| `deploy-pages.yml` | GitHub Pages 自动部署 workflow（放仓库 `.github/workflows/`） |
| `battle-forge-panel-local.json` | 本地联调版（APP_URL 指向 localhost:3000） |

完整应用源码见 **`battle-forge-app-src.zip`**（同目录上一级），推到 GitHub 仓库即可部署。

## 第一步 · 部署 GitHub Pages（应用本体）

1. 解压 `battle-forge-app-src.zip`，把 `battle-forge/` 目录里的**全部内容**推到一个新 GitHub 仓库（如 `battle-forge`，公开/私有均可）
2. 仓库 **Settings → Pages → Source 选 "GitHub Actions"**
3. 推送 main 分支，Actions 自动构建部署（约 1-2 分钟）
4. 应用地址：`https://<你的用户名>.github.io/<仓库名>/` —— 浏览器打开应能看到 Battle Forge 界面

## 第二步 · 酒馆配置（5 步，约 3 分钟）

1. **禁用旧面板**（必须）：扩展 → Regex → 找到 `dnnd-battle-panel` → 关闭开关。
   > 不禁用会怎样？旧面板会二次加工新面板的数据岛，面板顶部会显示红色污染警告。
2. **导入新正则**：Regex → 导入脚本 → 选 `battle-forge-panel.json`，
   然后把它**拖到正则列表最顶部**（必须先于「[美化]完整变量更新」运行，才能拿到原始变量数据）。
3. **导入旧楼隐藏器**：导入 `battle-forge-hide-legacy.json`（放哪都行，它只处理 4 楼以前的消息）。
4. **添加世界书条目**：角色卡编辑 → 世界书 → 新建条目 → 粘贴
   `battle-protocol-worldbook-entry.txt` 中虚线之间的内容。关键词建议：`battle, 战斗, 遭遇, battleresult`。
   > 强烈建议同时删除/禁用旧战斗协议条目中"逐回合输出 <battlecheck>"的指令，避免 AI 仍在战斗中自行结算。
5. **配置应用地址**：打一条含 `<battle>` 的消息让面板渲染出来，点面板右上角 **⚙ 应用地址**，
   粘贴你的 GitHub Pages 地址并保存（存于本浏览器，以后换地址也不用改正则）。
   也可以直接编辑正则脚本 replaceString 里的 `APP_URL` 常量。

## 数据流（三阶段闭环）

```
① 探索     <UpdateVariable> ──▶ 面板变量树 → 角色名单（HP/AC/六维/武器/法术位/法术书）
② 战前     <encounter> 敌卡 ──▶ 暂存 + 敌情简报（阵容/数值/难度预估，等待开战）
③ 集结     <battle> ──────────▶ 自动配装：敌方←敌卡，友方←角色名单（战前集结态）
④ 掷先攻   点「🎲 掷先攻 · 开战」→ 面板全员掷 d20+敏捷（2024：被突袭者劣势）→ 第 1 轮
⑤ 战斗中   你在面板操作（移动/武器/法术/通用动作；队友可切 👤玩家/🤖AI 操控）
⑥ 回传     面板「复制战报给 DM」→ <battleresult> 粘贴回酒馆
⑦ 战后     AI 按战报叙述剧情（伤亡/战利品/经验）+ 输出 <UpdateVariable> 应用建议补丁
```

**多楼层语义**（战斗不必在单一楼层内完成）：
- 战斗期间你正常发消息/AI 正常回复都不影响面板——每个楼层渲染的面板共享同一份战斗状态，
  最新楼层的面板持有操作权（旧楼层自动变只读镜像）。
- 战斗中 AI 若输出新的 `<battle>` 块：**同 ID 单位合并**（面板已结算的 HP/位置/先攻不会被
  AI 的过期数值覆盖——面板是结算权威，冲突会在日志中警告）；**只含新单位 = 增援入场**
  （面板自动为其掷先攻并插入回合序列，不打断当前回合）；**完全不相干的单位 = 新遭遇**
  （战场自动清场重置为集结态）。
- 增援的正确写法：新 `<encounter>` 敌卡 + 只含增援单位的 `<battle>` 块（见世界书条目）。

**战报按钮**在战斗进行中和结束后都能用：
- 进行中粘贴 → AI 只渲染 1-2 句战场氛围，**不会**替任何单位行动或结算
- 已结束粘贴 → AI 以战报数值为唯一事实叙述战后，并按「建议变量更新」同步角色 HP 等变量

## 面板行为说明

- **多楼层面板**：最近 4 楼各有一个面板，它们共享同一份战斗状态。最新楼层的面板为
  「主持面板」（跑 AI 驱动、应用新数据），旧楼层面板显示"同步视图"徽标（只读镜像，
  每 2 秒同步）。刷新页面/旧楼重挂载不会破坏当前战斗（消息哈希链防重复导入）。
- **离线降级**：GitHub Pages 不可达时显示轻量模式（先攻条 + HP 条 + 敌情简报摘要），不会白屏。
- **数据保存**：战斗状态自动保存在浏览器 localStorage（与酒馆同源），刷新不丢。
  注意：在酒馆内嵌面板与直接打开 Pages 网页属于不同存储分区，进度不互通——以酒馆内为主。
- **移动端**：390px 宽度自适应，行动栏/地图/战报按钮均可用。

## 常见问题

**Q：面板顶部红色警告"检测到旧版 dnnd-battle-panel"？**
按提示去 Regex 设置禁用旧脚本，然后刷新该楼层消息。

**Q：面板一直显示轻量模式？**
① 未配置应用地址（点 ⚙ 填写）；② GitHub Pages 未部署成功（检查 Actions 日志）；
③ 网络无法访问 GitHub（挂代理或本地部署 `battle-forge-panel-local.json` + `npm run dev`）。

**Q：敌人数据不全（没有六维/动作表）？**
那是没有敌卡的裸 <battle> 单位。让 AI 按世界书协议先输出 <encounter> 敌卡再开战；
或用面板「敌卡」标签手动设计。内置 26 种预设怪物会按名字自动配装。

**Q：AI 还在战斗里掷骰/输出 battlecheck？**
世界书条目优先级不够。把新条目的插入深度调深（@D ≥ 旧战斗协议条目），
或直接禁用旧的「[协议] 战斗地图数据」条目。

**Q：想把某楼的面板变回可操作？**
滚动到最新一条带面板的消息操作即可；旧楼面板是只读同步视图，这是防多面板
同时驱动 AI / 旧数据回写的保护机制。

## 隐私与安全

- 应用完全静态（GitHub Pages），无后端、无遥测；所有数据保存在你的浏览器本地
- 面板与酒馆之间只通过 postMessage 传递消息文本本身，不读写酒馆的 Cookie 或 API
